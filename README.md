# 티노코코 동시점프 러너 (v2)

크롬 오프라인 공룡 게임과 같은 구조의 달리기 게임. 시작 전에 티노 또는 코코 중 한 명을 고르고, 고른 한 명이 달리다가 스페이스바·탭으로 점프해 물웅덩이와 돌멩이를 넘는다.

- 빌드 없음, 프레임워크 없음. 바닐라 JS + Canvas 한 파일(`index.html`) + 이미지 `assets/` 폴더.
- 구글 코드·에셋은 쓰지 않았다. 메카닉만 참고한 오리지널 구현.

## v2 변경점 (v1 대비)

v1 위에 수정했다. 구조는 그대로 두고 아래 네 가지를 바꿨다.

1. **방향 수정**: 원본 run 포즈는 얼굴이 왼쪽을 향한다. 좌우 반전본 `*_run_flip.png`를 새로 만들어 게임은 반전본을 쓴다. 원본(`*_run_v2.png`)은 그대로 두었다. jump·laugh 포즈는 정면에 가까워서 반전하지 않았다.
2. **캐릭터 선택 + 1인 플레이**: 시작 화면에 티노·코코 카드 2개(이미지, 이름, 한 줄 설명). 선택 전에는 "출발!" 버튼이 비활성이고 캔버스를 눌러도 시작되지 않는다. 선택은 `localStorage`(키 `tinokoko-dino-char`)에 저장된다. 게임에서는 고른 한 명만 달린다. 충돌 후에는 "다시 하기"와 "캐릭터 바꾸기" 버튼이 나온다.
3. **넘을 수 있는 판정**: 두 캐릭터를 나란히 두던 묶음 판정을 버리고 한 명 기준으로 바꿨다. 판정 폭을 표시 폭의 50%로 좁혔고, 장애물 크기를 명세 범위 안에 맞췄다. 계산은 아래 "판정 수치" 참조.
4. **디자인**: 카드형 스테이지(둥근 모서리, 그림자), 세로 그라데이션 하늘, 2겹 언덕(뒤쪽이 더 느림), 느리게 흐르는 구름, 질감선이 있는 땅. 헤더에 제목과 점수 pill 2개(⭐ 넘은 장애물 / 최고 ⭐), 원형 소리 버튼. 시작·종료 패널은 반투명 흰 패널에 둥근 버튼이다. 파스텔은 채도를 조금 낮췄다.

추가로 `?test=1` 자동 검증 모드를 넣었다 (아래 "자동 검증").

## 파일 구성

```
tinokoko-dino-game/
├── index.html                 게임 전체 (CSS·JS 인라인, 한국어 주석)
├── README.md                  이 문서
└── assets/
    ├── tino_run_v2.png        티노 달리기 원본 (얼굴 왼쪽, 높이 512px)
    ├── tino_run_flip.png      티노 달리기 좌우 반전본 (게임이 쓰는 파일)
    ├── tino_jump_v2.png       티노 점프 (정면에 가까워 반전 안 함)
    ├── tino_laugh_v2.png      티노 웃음 (부딪힌 뒤)
    ├── coco_run_v2.png        코코 달리기 원본 (얼굴 왼쪽)
    ├── coco_run_flip.png      코코 달리기 좌우 반전본 (게임이 쓰는 파일)
    ├── coco_jump_v2.png       코코 점프
    └── coco_laugh_v2.png      코코 웃음
```

`*_v2.png` 원본은 승인된 이미지(`tinokoko-pipeline/library/assets/*_v2.png`)를 높이 512px 이하로 줄인 복사본이다. 반전본은 이 복사본을 PIL `FLIP_LEFT_RIGHT`로 뒤집은 것이다. 새로 그리거나 생성한 이미지는 없다.

## 실행 방법

**방법 1: 파일 열기 (가장 간단)**
`index.html`을 브라우저로 더블클릭하거나 주소창에 끌어다 놓는다. `file://`에서도 동작하도록 모든 경로는 상대경로다.

**방법 2: 로컬 서버**
```bash
cd ~/workspace/tinokoko-dino-game
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000 접속
```

## 조작법

| 입력 | 동작 |
|---|---|
| 카드 탭·클릭 | 캐릭터 선택 (시작 화면에서 언제든 변경) |
| "출발!" 버튼 / 스페이스바 / ↑ / 화면 탭 | 선택한 캐릭터로 출발 + 첫 점프 (선택 전에는 무시) |
| 스페이스바 / ↑ / 화면 탭 (달리는 중) | 점프 |
| 부딪힌 뒤 "다시 하기" 또는 입력 | 같은 캐릭터로 재시작 (부딪힌 직후 약 0.5초는 캔버스 입력 무시) |
| 부딪힌 뒤 "캐릭터 바꾸기" | 시작 화면으로 돌아가 다시 고른다 |
| 우상단 🔊 / 🔇 버튼 | 소리 켜기·끄기 |

- 공중에서 누르는 입력은 무시된다 (이중 점프 없음).
- 장애물을 완전히 넘을 때마다 ⭐ +1.
- 최고 기록은 `localStorage`(키 `tinokoko-dino-best`)에 저장된다. 저장이 막혀 있어도 게임은 그대로 동작한다.

## 판정 수치 (계산 근거)

v1 물리 값은 유지했다 (중력 1000, 점프 높이 140, 시작 속도 170, 최고 속도 360, 가속 3). 아래는 그 값으로 한 캐릭터·최소 장애물 조건을 계산한 결과다.

**캐릭터 크기와 판정 박스**
- 표시 높이 `DISPLAY_H = 120px` (명세 110~120 범위). 폭은 원본 비율대로: 티노 `120 × 413/512 ≈ 96.8px`, 코코 `120 × 363/512 ≈ 85.1px`.
- 판정 박스: 좌우 25%씩 안쪽 → **폭 = 표시 폭의 50%** (명세 50~60% 범위). 티노 `48.4px`, 코코 `42.5px`. 위쪽 25%를 줄여 높이 `90px`, 발끝은 줄이지 않는다.

**장애물 크기** (명세 범위 안)
- 물웅덩이 `52 × 16px` (명세 44~60), 돌멩이 `38 × 40px` (명세 32~44).
- 장애물 판정 박스도 같은 규칙(좌우·위 25% 안쪽)을 쓴다: 물웅덩이 판정 폭 26px, 돌멩이 19px.

**점프 체공 시간 (반동 포함)**
- `JUMP_V = √(2·g·H) = √(2·1000·140) ≈ 529.15 px/s`
- `AIR_TIME = (2·JUMP_V + 2·0.2·JUMP_V) / g = 2.4 × 529.15 / 1000 ≈ 1.270 s`

**조건 1: 한 번의 점프로 넘기 (시작 속도와 최고 속도 모두)**
`판정 폭 + 장애물 최대 폭 + 여유 60px ≤ 속도 × AIR_TIME`
- 판정 폭 최대 48.4 + 장애물 최대 52 + 60 = **160.4px**
- 시작 속도: `170 × 1.270 = 215.9px` ≥ 160.4 ✓ (여유 55.5px)
- 최고 속도: `360 × 1.270 = 457.2px` ≥ 160.4 ✓

**조건 2: 점프 중 높이가 장애물을 넘는지**
- 돌멩이(h 40): 점프 후 높이 `lift(t) = JUMP_V·t − ½·g·t² ≥ 40`인 구간은 `t ∈ [0.082s, 0.976s]`.
- 자동 점프 타이밍: 장애물 판정 박스 왼쪽 끝이 캐릭터 판정 박스 오른쪽 끝에서 `속도 × 0.2s` 안쪽일 때 점프. 최악 조건(시작 속도 170, 물웅덩이 판정 폭 26)에서 겹침 구간은 `0.2s ~ 0.2 + (26+48.4)/170 ≈ 0.64s`로, 40px 이상 구간 안에 들어간다 ✓. 물웅덩이(h 16)는 더 쉽다.

**조건 3: 장애물 간격 (착지 후 다음 점프 가능)**
- `MIN_GAP = ceil(360 × 1.270 + 60) = 518px`, 간격 = `518 ~ 698px` (`EXTRA_GAP 180`).
- 최악 조건(최고 속도 360)에서 다음 장애물이 자동 점프 지점에 도달하는 시간은 `(52 + 518) / 360 ≈ 1.58s` ≥ `AIR_TIME 1.27s` ✓. 착지 전에 다음 점프 지점이 오지 않는다.

## 자동 검증 (`?test=1`)

`?test=1`로 열면 시작 화면을 건너뛰고 바로 달리며, 자동 점프 조종사가 장애물을 넘는다. 충돌 없이 점수 5에 도달하면 PASS, 충돌하거나 60초(게임 시간) 안에 못 넘으면 FAIL이다. 결과는 화면 왼쪽 위 배지, `console`, `document.title`, `window.__TEST_RESULT`에 남는다.

- 캐릭터 지정: `?test=1&char=coco` (생략하면 티노). 테스트 중에는 저장된 선택을 바꾸지 않는다.
- 판정은 실제 게임 충돌 로직으로 한다. 조종사는 점프 타이밍만 정하고, 충돌·점수 계산은 일반 플레이와 같다.

**결과 (2026-10-30, 헤드리스 Chromium, 최종 파일 기준)**

| 실행 | 캐릭터 | 결과 | 점수 | 페이지 오류 |
|---|---|---|---|---|
| 1 | 티노 | PASS | 5/5 | 없음 (`favicon.ico` 404 1건만 있음. 파비콘은 v1부터 없다) |
| 2 | 티노 | PASS | 5/5 | 없음 |
| 3 | 티노 | PASS | 5/5 | 없음 |
| 4 | 코코 | PASS | 5/5 | 없음 |
| 5 | 코코 | PASS | 5/5 | 없음 |
| 6 | 코코 | PASS | 5/5 | 없음 |
| 7 | 코코 (`file://`로 열기) | PASS | 5/5 | 없음 |

장애물 배치는 `Math.random()`으로 정해져서 실행마다 다르다. 위 여섯 번은 서로 다른 배치로 돌았다.

## 검증 결과

1. **파일과 참조 일치**: `index.html`이 참조하는 경로 6개(run은 반전본, jump·laugh는 원본)와 선택 카드 이미지 2개가 실제 파일과 일치한다. 404는 없다 (`favicon.ico` 제외).
2. **로컬 서버 200**: `python3 -m http.server`로 띄운 뒤 `index.html`과 이미지 6장이 모두 200을 받았다.
3. **JS 문법**: 인라인 `<script>`를 뽑아 `node --check` 통과.
4. **헤드리스 스크린샷(선택 화면)**: 티노·코코 카드와 캔버스 미리보기에서 두 캐릭터 모두 얼굴이 오른쪽을 향한다. 선택 전에는 "출발!"이 비활성이다.
5. **헤드리스 일반 플레이**: 코코 선택 → 출발 → 점프 없이 충돌 → 종료 패널 표시 → "캐릭터 바꾸기" → 시작 화면 복귀, 선택(코코)이 유지되었다. 선택 전 캔버스 탭은 시작되지 않았다. 페이지 예외는 없었다.
6. **`?test=1` PASS**: 위 표 참조.

달리는 중의 장면은 스크린샷으로 따로 검수하지 않았다. 시각 확인은 선택 화면과 종료 화면에 한정된다.

## 알려진 한계

- **브라우저 범위**: 헤드리스 Chromium 한 종류에서만 확인했다. 사파리, 파이어폭스, 실제 모바일 기기는 확인하지 않았다.
- **소리는 귀로 확인하지 않았다**: WebAudio 코드는 오류 없이 도는 것만 확인했다.
- **플레이 체감은 미확인**: 자동 점프 조종사로 넘을 수 있음을 확인했다. 사람이 직접 칠 때의 체감 난이도와 유아 대상 테스트는 하지 않았다. 난이도 값은 추정이다.
- **판정 박스는 시각과 조금 다르다**: 좌우·위쪽을 줄인 박스라서 이미지 가장자리가 닿아도 충돌이 안 날 수 있다. 관대한 판정을 의도한 것이다.
- **재시작 시 점수 초기화**: 부딪힌 뒤에는 점수가 화면에 유지되고, 재시작하면 0으로 돌아간다.
- **범위 밖 (의도적으로 안 넣음)**: 앱스토어·서버·로그인·분석·광고·결제, 난이도 선택, 레벨, 더블점프, 숙이기, 캐릭터 신규 이미지 생성, 프레임워크.
