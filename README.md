# 티노코코 동시점프 러너 (v3)

크롬 오프라인 공룡 게임과 같은 구조의 달리기 게임. 시작 전에 티노 또는 코코 중 한 명을 고르고, 고른 한 명이 달리다가 스페이스바·탭으로 점프해 물웅덩이와 돌멩이를 넘는다. v3부터 물웅덩이는 밟아도 게임이 끝나지 않고, 게임이 끝나는 건 돌멩이에 부딪혔을 때뿐이다.

- 빌드 없음, 프레임워크 없음. 바닐라 JS + Canvas 한 파일(`index.html`) + 이미지 `assets/` 폴더.
- 구글 코드·에셋은 쓰지 않았다. 메카닉만 참고한 오리지널 구현.

## v3 변경점 (v2 대비)

사용자 피드백: "난이도가 너무 높다. 애들이 하기엔 더 쉽고 이지하고 캐주얼하게." 구조·디자인·캐릭터 선택·사운드 체계는 그대로 두고 수치와 규칙만 바꿨다.

1. **속도**: 시작 170 → 105 px/s, 최고 360 → 175 px/s, 가속 3 → 0.8 px/s².
2. **점프**: 중력 1000 → 780, 점프 높이 140 → 175 px. 점프 버퍼 0.18초 추가: 공중에서 누른 입력을 버리지 않고 기억했다가, 착지(첫 접촉)하자마자 점프한다.
3. **판정**: 캐릭터 판정 폭을 표시 폭의 50% → 38%, 위쪽 여유 25% → 35%로. 장애물 판정 폭은 시각 폭의 50%, 물웅덩이는 판정 높이도 절반.
4. **물웅덩이 무해화**: 지상에서 밟으면 물방울 10개가 튀고, 첨벙 소리(기존 충돌음 재활용), 웃음 포즈 0.35초 뒤 달리기 포즈로 돌아간다. 점수는 그대로 +1. 점프로 넘어도 +1. 게임 오버는 돌멩이에만. 장애물 중 돌멩이 비율은 35%, 나머지는 물웅덩이.
5. **장애물 간격**: 최소 간격 = max(속도 × 2.2초, 420px), 랜덤 상한은 최소 간격의 1.6배. 재시작 후 첫 장애물은 1.2초 뒤에 나온다.
6. **테스트 훅**: 기존 `?test=1`(자동 점프)은 그대로. 새로 `?test=1&force=puddle&nojump=1`(물웅덩이만, 점프 금지) 추가.

## v2 변경점 (v1 대비)

v1 위에 수정했다. 구조는 그대로 두고 아래 네 가지를 바꿨다.

1. **방향 수정**: 원본 run 포즈는 얼굴이 왼쪽을 향한다. 좌우 반전본 `*_run_flip.png`를 새로 만들어 게임은 반전본을 쓴다. 원본(`*_run_v2.png`)은 그대로 두었다. jump·laugh 포즈는 정면에 가까워서 반전하지 않았다.
2. **캐릭터 선택 + 1인 플레이**: 시작 화면에 티노·코코 카드 2개(이미지, 이름, 한 줄 설명). 선택 전에는 "출발!" 버튼이 비활성이고 캔버스를 눌러도 시작되지 않는다. 선택은 `localStorage`(키 `tinokoko-dino-char`)에 저장된다. 게임에서는 고른 한 명만 달린다. 충돌 후에는 "다시 하기"와 "캐릭터 바꾸기" 버튼이 나온다.
3. **넘을 수 있는 판정**: 두 캐릭터를 나란히 두던 묶음 판정을 버리고 한 명 기준으로 바꿨다.
4. **디자인**: 카드형 스테이지(둥근 모서리, 그림자), 세로 그라데이션 하늘, 2겹 언덕(뒤쪽이 더 느림), 느리게 흐르는 구름, 질감선이 있는 땅. 헤더에 제목과 점수 pill 2개(⭐ 넘은 장애물 / 최고 ⭐), 원형 소리 버튼. 시작·종료 패널은 반투명 흰 패널에 둥근 버튼이다.

## 실행 방법

**방법 1: 파일 열기 (가장 간단)**
`index.html`을 브라우저로 더블클릭하거나 주소창에 끌어다 놓는다. `file://`에서도 동작하도록 모든 경로는 상대경로다.

**방법 2: 로컬 서버**
```bash
cd ~/workspace/tinokoko-dino-game
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000 접속
```

## 조작법

| 입력 | 동작 |
|---|---|
| 카드 탭·클릭 | 캐릭터 선택 (시작 화면에서 언제든 변경) |
| "출발!" 버튼 / 스페이스바 / ↑ / 화면 탭 | 선택한 캐릭터로 출발 + 첫 점프 (선택 전에는 무시) |
| 스페이스바 / ↑ / 화면 탭 (달리는 중) | 점프 (공중에서 누르면 착지 직전 0.18초 안의 입력만 기억해 착지 때 점프) |
| 부딪힌 뒤 "다시 하기" 또는 입력 | 같은 캐릭터로 재시작 (부딪힌 직후 약 0.5초는 캔버스 입력 무시) |
| 부딪힌 뒤 "캐릭터 바꾸기" | 시작 화면으로 돌아가 다시 고른다 |
| 우상단 🔊 / 🔇 버튼 | 소리 켜기·끄기 |

- 공중에서 점프는 나가지 않는다 (이중 점프 없음). 착지 직전에 누른 입력만 착지 순간 한 번 실행된다.
- 장애물을 완전히 넘을 때마다 ⭐ +1. 물웅덩이는 밟아도 ⭐ +1이고 게임은 계속된다.
- 최고 기록은 `localStorage`(키 `tinokoko-dino-best`)에 저장된다. 저장이 막혀 있어도 게임은 그대로 동작한다.

## 판정 수치 (v3 계산 근거)

v3 값: 중력 780, 점프 높이 175, 시작 속도 105, 최고 속도 175, 가속 0.8, 표시 높이 120px. 아래는 이 값에서 계산한 결과다 (`JUMP_V`, `AIR_TIME`은 코드에서 같은 식으로 계산된다).

**캐릭터 크기와 판정 박스**
- 표시 높이 `DISPLAY_H = 120px`. 폭은 원본 비율대로: 티노 `120 × 413/512 ≈ 96.8px`, 코코 `120 × 363/512 ≈ 85.1px`.
- 판정 박스: 좌우 31%씩 안쪽 → **폭 = 표시 폭의 38%**. 티노 `36.8px`, 코코 `32.3px`. 위쪽 35%를 줄여 높이 `78px`, 발끝은 줄이지 않는다.

**장애물 크기와 판정 박스**
- 물웅덩이 `52 × 16px`, 돌멩이 `38 × 40px` (명세 범위 안).
- 판정 폭: 좌우 25%씩 안쪽 → 시각 폭의 50%. 물웅덩이 `26px`, 돌멩이 `19px`.
- 판정 높이: 물웅덩이는 절반 → `8px` (발끝 쪽 8px). 돌멩이는 위쪽 25%를 줄여 `30px`.

**점프 물리**
- `JUMP_V = √(2·g·H) = √(2·780·175) ≈ 522.5 px/s`
- `AIR_TIME = (2·JUMP_V + 2·0.2·JUMP_V) / g = 2.4 × 522.5 / 780 ≈ 1.608 s` (착지 반동 포함)

**조건 1: 한 번의 점프로 옆을 지나가기 (점프 거리 vs 필요 거리)**
- 시작 속도 105: 점프 중 이동 거리 `105 × 1.608 ≈ 168.8px`
- 최고 속도 175: 점프 중 이동 거리 `175 × 1.608 ≈ 281.3px`
- 필요 거리 = 캐릭터 판정 폭 + 장애물 판정 폭. 티노·물웅덩이 `36.8 + 26 = 62.8px`, 티노·돌멩이 `36.8 + 19 = 55.8px`.
- 최고 속도 점프 거리 281px ≥ 필요 거리 62.8px. 여유 약 4.5배.

**조건 2: 돌멩이 위로 넘는 높이**
- 돌멩이 판정 윗부분은 높이 30px. 캐릭터 판정 아랫변이 30px보다 높이 떠 있어야 겹치지 않는다 (`lift ≥ 30`).
- `lift(t) = JUMP_V·t − ½·g·t² ≥ 30`인 구간: `t ∈ [0.060s, 1.280s]`, 길이 1.22초.
- 최고 속도에서 이 구간 동안 이동 거리 `175 × 1.22 ≈ 213px` ≥ 필요 거리 55.8px. 돌멩이 위를 충분히 지나간다.
- 자동 점프 조종사: 장애물 판정 왼쪽 끝이 캐릭터 판정 오른쪽 끝에서 `속도 × 0.2s` 안쪽이면 점프. 시작 속도에서 겹침은 `t = 0.2s`부터 `0.2 + 55.8/105 ≈ 0.73s`까지이고, 이 구간은 `lift ≥ 30` 구간 안에 있다.

**조건 3: 장애물 간격 (착지 후 다음 점프 가능)**
- 최소 간격 = `max(속도 × 2.2, 420)`. 시작 속도 105에서 420px (`4.0s`), 최고 속도 175에서도 420px (`2.4s`). 속도 175에서 `2.2 × 175 = 385 < 420`이라 420px 하한이 적용된다.
- 랜덤 상한은 최소 간격의 1.6배 (420 ~ 672px).
- 최고 속도에서 최소 간격을 지나는 시간 `2.40s > AIR_TIME 1.608s`. 착지 전에 다음 점프 지점이 오지 않는다.

**조건 4: 재시작 직후**
- 재시작 후 첫 장애물은 `FIRST_DELAY = 1.2s` 뒤에 나온다.

## 자동 검증

두 모드 모두 시작 화면을 건너뛰고 바로 달린다. 결과는 화면 왼쪽 위 배지, `console`, `document.title`, `window.__TEST_RESULT`에 남는다. 판정은 실제 게임 충돌 로직으로 한다.

| URL | 조종 | PASS 조건 | FAIL 조건 |
|---|---|---|---|
| `?test=1` (`&char=coco`로 코코) | 자동 점프 조종사 | 충돌 없이 장애물 5개 넘음 | 충돌, 또는 60초(게임 시간) 안에 못 넘음 |
| `?test=1&force=puddle&nojump=1` | 점프 금지 (입력도 막음). 물웅덩이만 나옴 | 충돌 없이 물웅덩이 3개 통과 (점수 3 이상) | 충돌, 또는 60초 안에 3개 못 넘음 |

- 캐릭터 지정: `?test=1&char=coco` (생략하면 티노). 테스트 중에는 저장된 선택을 바꾸지 않는다.
- `force=puddle`만 따로 주면 물웅덩이만 나온다. `nojump=1`만 따로 주면 점프 입력이 막힌다.

**검증 결과 (2026-10-30, 헤드리스 Chromium 1248, 최종 파일 기준)**

| 테스트 | 실행 | 결과 | 점수 | 페이지 오류 |
|---|---|---|---|---|
| `?test=1` 티노 | 3회 | PASS 3/3 | 5/5 | 없음 |
| `?test=1&char=coco` 코코 | 3회 | PASS 3/3 | 5/5 | 없음 |
| `?test=1&force=puddle&nojump=1` | 3회 | PASS 3/3 | 3/3 | 없음 |

- 장애물 배치는 `Math.random()`으로 정해져서 실행마다 다르다. 위 실행들은 서로 다른 배치로 돌았다.
- 부정 확인: 돌멩이가 섞이는 `?test=1&nojump=1`을 3회 돌리면 3회 모두 돌멩이에 부딪혀 FAIL(충돌, 점수 3·0·1)이다. 돌멩이만 게임을 끝낸다.

## 검증 결과

1. **파일과 참조 일치**: `index.html`이 참조하는 이미지 경로가 모두 실제 파일과 맞는다. v3에서 이미지 파일은 바뀌지 않았다.
2. **JS 문법**: 인라인 `<script>`를 뽑아 `node --check` 통과.
3. **물웅덩이 밟기 (디버그 사본으로 프로브)**: 점프 없이 물웅덩이를 밟으면 `splashLeft`가 0.35초 동안 유지되고, 물방울 10개가 생기고, 공중 프레임은 0이다. 웃음 포즈 상태의 화면을 캡처해 확인했다.
4. **점프 버퍼 (디버그 사본으로 프로브)**: 반동 중에 누른 입력은 반동이 끝나는 착지 순간 점프로 실행됐다. 첫 접촉 약 0.29초 전에 누른 입력은 버퍼(0.18초) 밖이라 무시됐다.

프로브는 저장소 밖 임시 사본(`index.html` 한 줄 추가)에서 돌렸다. 저장소의 `index.html`에는 테스트용 코드를 넣지 않았다.

## 알려진 한계

- **브라우저 범위**: 헤드리스 Chromium 한 종류에서만 확인했다. 사파리, 파이어폭스, 실제 모바일 기기는 확인하지 않았다.
- **소리는 귀로 확인하지 않았다**: 물웅덩이 첨벙도 기존 충돌음을 재활용한 것이라 코드 경로만 확인했다.
- **플레이 체감은 미확인**: 자동 조종사로 넘을 수 있음과 물웅덩이 무해화는 확인했다. 사람이 직접 칠 때의 체감 난이도와 3세 아이 대상 테스트는 하지 않았다. 속도·중력·간격 값은 계산과 추정에 따른 것이다.
- **웃음 포즈 이미지**: 물웅덩이를 밟았을 때 쓰는 웃음 이미지는 v2의 `*_laugh_v2.png`를 그대로 쓴다. 새 이미지는 만들지 않았다.
- **판정 박스는 시각과 다르다**: 좌우·위쪽을 줄인 박스라서 이미지 가장자리가 닿아도 충돌이 안 날 수 있다. 관대한 판정을 의도한 것이다.
- **재시작 시 점수 초기화**: 부딪힌 뒤에는 점수가 화면에 유지되고, 재시작하면 0으로 돌아간다.
- **범위 밖 (의도적으로 안 넣음)**: 앱스토어·서버·로그인·분석·광고·결제, 난이도 선택, 레벨, 더블점프, 숙이기, 캐릭터 신규 이미지 생성, 프레임워크.
