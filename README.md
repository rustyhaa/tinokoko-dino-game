# 티노코코 달리기 (chrome-feel 브랜치) — 크롬 공룡 게임의 티노코코 버전

크롬 오프라인 공룡 게임의 골격 그대로, 달리는 캐릭터만 티노/코코로 바꾼 버전.

## 5차 변경 (2026-10-31): 화면 크기 선택 (보통 · 크게 · 전체)

1920×1080 데스크탑에서 게임 화면이 작게 나온다는 요청에 맞춰, 헤더 오른쪽 배속 옆에 화면 크기 버튼을 추가했다. 게임 로직·점프 물리·속도·장애물 규칙은 바꾸지 않았다.

| 크기 | 컨테이너 최대 폭 | 캔버스 높이 | 비고 |
|---|---|---|---|
| 보통 (기본) | 960px | 가로 × 0.42, 360~420px | 4차까지와 동일 |
| 크게 | 1440px | 가로 × 0.42, 420~680px | 1920 폭에서 약 591px |
| 전체 | 제한 없음 (좌우 여백 16px) | 창 높이 − 170px, 420~900px | 1920×1080에서 900px |

- 게임 중에도 바꿀 수 있다. 크기 버튼은 캔버스 밖 HTML 버튼이라 점프를 일으키지 않는다.
- 전환 시 월드 좌표(장애물·장치·꽃)는 그대로이고 축척만 바뀐다. 캐릭터는 월드 x에 고정이라 화면 안에 남는다.
- 선택은 `localStorage`(키 `tinokoko-dino-size`)에 저장되고 새로고침 후에도 유지된다.
- 좁은 화면: 세 모드 모두 폭은 `min(설정값, 100%)`이고 390px 폭에서 가로 넘침은 없다 (헤더는 `flex-wrap`).
- 코드: `SIZE_H`, `applySize()`, `setSize()`, `resize()`의 높이 계산.
- 테스트 전용 파라미터 `?test=1&size=normal|large|full` (저장값을 읽거나 쓰지 않는다).

## 4차 변경 (2026-10-31): 축하 · 낮/밤 · 꽃길 · 과일 · 응원

난이도·조작은 그대로다. 점프 물리(체공 0.78초), 속도 곡선, 배속 0.7/1/1.4, 돌멩이 스폰 규칙을 바꾸지 않았다. 새 사망 조건도 없다. 추가한 것은 전부 보너스·보호·연출이다.

1. **500점 축하 + 꽃길**
   - 점수가 500의 배수를 넘을 때마다 1회: 캐릭터 주변에 컬러 별·동그라미 파티클 (최대 40개, 약 1초), 팡파레 (`sfxFanfare`). 같은 순간의 100점 블립은 팡파레가 대신한다. 게임은 멈추지 않는다.
   - 꽃길: 달리는 동안 지면선 위에 5잎 꽃이 90~140 월드 px 간격으로 피어나 왼쪽으로 흐른다. 색은 4종 순환, 최대 60송이. 장애물·장치 판정과 무관하다.
   - 코드: `celebrate()`, `spawnFlower()`, `updateCelebs()`, `drawFlower()`.
2. **낮/밤**: 700점마다 낮과 밤이 번갈아 바뀐다 (0~699 낮, 700~1399 밤). 경계에서 0.6초에 걸쳐 색이 변한다.
   - 밤: 바탕 짙은 슬레이트 `#2E3748` (순수 검정 아님), 지면·돌멩이·HUD 글자 밝은 회색 `#D5DBE5`, 하늘에 초승달과 고정 시드 별 16개 (약하게 깜빡). 캐릭터 뒤에는 연한 원형 후광.
   - 밤이라고 속도·장애물·장치 규칙은 달라지지 않는다. 낮/밤 전환 순간에 종소리 1음 (볼륨 0.05).
   - 코드: `isNightAt()`, `drawSky()`, `drawHalo()`, `mixColor()`, `nightMix`.
3. 모자 꾸미기는 사용자 반려로 삭제 (별 누적 저장·모자 그림·선택 화면 별 진행 표시 모두 제거. 별 수집 +50점과 HUD 별 카운트는 유지).
4. **효과음 추가** (WebAudio 신스, `tone()`에 `delay` 인자 추가): 과일 `sfxFruit` (뽁-뽕), 축하 팡파레 `sfxFanfare` (523→659→784→1047, 오디오 시계로 예약), 밤 전환 종소리 `sfxNight`. 모두 음소거를 따른다. 방패 파손은 기존 소리를 그대로 썼다 (노이즈는 추가하지 않음).
5. **선택하지 않은 쌍둥이의 응원**
   - 출발 응원: 시작 직후 선택하지 않은 캐릭터의 laugh 그림이 60% 크기로 플레이어 뒤쪽에 서 있다가 세계와 함께 왼쪽으로 흘러간다. 판정 없음.
   - 축하 응원: 500점 축하 때 오른쪽 아래 구석에 50% 크기로 약 1초간 나타나 까딱인다. 지면선 아래라 장애물을 가리지 않는다.
6. **컬러 과일**: 장치 종류 가중치 `ITEM_WEIGHTS` (별 2 : 과일 1 : 하트 2). 과일 3종 (사과·포도·오렌지)은 지면 근처에 나와 달리기 자세로 닿는다. 먹으면 +30점, HUD에 과일 아이콘 + 개수, 과일 소리, 컬러 파티클 7개. 흰 반짝임과 얇은 링으로 돌멩이와 구분한다.
   - 가중치는 브리프의 5 : 3 : 2 대신 2 : 1 : 2로 잡았다. 5 : 3 : 2는 하트 등장이 지금의 50%에서 20%로 줄어 "하트가 눈에 띄게 줄지 않게" 조건과 충돌한다. 장치는 한 번에 하나, 8~15초 간격은 그대로이므로 과일을 넣은 만큼 별과 하트가 줄어든다. 값 하나로 바꿀 수 있다.

**HUD 변화**: 방패 하트는 별·과일 옆으로 옮겼다 (x 80 → 160). 3차 설명의 방패 위치는 이 기준으로 읽는다. 100점 블립은 500점 배수에서 팡파레로 대체된다.

## 3차 변경 (2026-10-30): 실루엣 삭제 · 게임 중 배속 · 중간 장치

1. **실루엣 삭제**: 코드 드로잉 스프라이트(몸통·다리·눈 패치 데이터와 그리기 함수), 스타일 선택 토글, `tinokoko-dino-style` 저장을 전부 지웠다. 캐릭터는 실사 흑백(`assets/*_gray.png`)만 쓴다. 달리기 = run 1장 + bobbing, 점프 = jump, 충돌 = laugh. 판정 박스는 그대로다.
2. **게임 중 배속 변경**: 상단 [0.7배] [1배] [1.4배] 버튼 또는 키 1 · 2 · 3. 시작 패널의 배속 선택과 같은 값(`tinokoko-dino-speed`)을 공유한다.
   - 버튼은 캔버스 밖에 있어 눌러도 점프하지 않는다.
   - 바꾸는 순간 현재 속도도 같은 비율로 바뀐다. 체공 시간은 0.767초로 그대로이고, 점프 수평거리만 속도에 비례해 달라진다.
3. **중간 장치 2종** (`?forceitem=star|heart`은 스크린샷용 강제 등장, 테스트 모드에서는 무시):

   - 코코: 큰 둥근 머리, 눈 뒤 큰 흰 타원 패치(지금보다 크게), 작은 둥근 등지느러미, 흰 배 넓게, 둥근 꼬리지느러미.
   - 유지: 옆모습, 몸통 단일 함수, 다리 2프레임, 점프=다리 접음, 충돌=눈 X.
2. **스타일 선택**: 시작 패널에 [실루엣] [실사 흑백]. 선택은 `localStorage`(`tinokoko-dino-style`)에 저장. 게임오버 후 "캐릭터 바꾸기"에서도 바꿀 수 있다.
   - 실사 흑백은 `assets/*_gray.png` 6장(승인 일러스트를 PIL로 흑백 변환, 알파 유지, 높이 512): run 1장 + bobbing(달리기 2프레임 중 한쪽에서 2px 위로), 점프 = jump, 충돌 = laugh.
   - 표시 높이(72)와 판정 박스는 실루엣과 같다. 스타일을 바꿔도 난이도는 같다.
3. **배속 선택**: [0.7배] [1배] [1.4배], 기본 1배, `localStorage`(`tinokoko-dino-speed`)에 저장. 배율은 시작·최고 속도와 가속(속도 곡선 전체)에 곱한다. 체공 시간 곡선은 그대로라 점프 수평거리는 속도에 비례한다. HUD(HI 왼쪽)에 현재 배속을 표시한다. 점수는 실제 이동 거리 기준이라 배속이 높으면 빨리 오른다.

# 티노코코 동시점프 러너 (v4)

크롬 오프라인 공룡 게임과 같은 구조의 달리기 게임. 시작 전에 티노 또는 코코 중 한 명을 고르고, 고른 한 명이 달리다가 스페이스바·탭으로 점프해 물웅덩이와 돌멩이를 넘는다. 물웅덩이는 밟아도 게임이 끝나지 않고(첨벙), 게임이 끝나는 건 돌멩이에 부딪혔을 때뿐이다.

- 빌드 없음, 프레임워크 없음. 바닐라 JS + Canvas 한 파일(`index.html`) + 이미지 `assets/` 폴더.
- 구글 코드·에셋은 쓰지 않았다. 메카닉만 참고한 오리지널 구현.

## v4 변경점 (v3 대비): "속도감은 있으면서 난이도는 낮게"

사용자 피드백: v3는 속도를 죽여서 속도감이 없다. 크롬 공룡처럼 빠르지만 할 만하게 바꿀 것. v4는 크롬 공룡이 빠른데도 할 만한 구조 네 가지를 옮겨 왔다.

1. **점프가 속도에 비례**: 체공 시간 T를 속도와 거의 무관하게 고정하고 `JUMP_V = g·T/2`로 둔다. 체공 중 수평 이동거리 = 속도 × T라서 빨라질수록 점프도 같이 멀리 간다. "점프 거리 ÷ 필요 클리어 거리" 비율이 시작 속도에서 2.9, 최고 속도에서 6.0으로, 빨라질수록 오히려 넉넉해진다.
2. **스내피한 점프**: 중력 780 → 2400, 체공 1.6초 → 약 0.77초. 착지 반동은 없앴다. 반동은 체공을 늘리고 타이밍을 흐려서 크롬식 점프와 맞지 않는다.
3. **시간 기준 장애물 간격**: 앞 장애물 꼬리가 지나간 뒤 다음 장애물 머리가 오기까지 최소 1.35초 + 랜덤 0~0.7초. 거리로 잡지 않고 시간으로 잡아서, 어떤 속도에서도 반응 시간이 같다. 간격이 줄어들지 않도록 하는 방법: 속도는 별 개수로만 오른다. 그래서 스폰 시점에 "화면에 있는 미통과 장애물을 모두 넘었을 때의 목표 속도"로 거리를 잡는다. 그 사이 실제 속도는 이 값을 넘을 수 없으니 시간 간격이 보장된다.
4. **속도감 연출**
   - 달리기 애니메이션: run 포즈와 walk 포즈를 번갈아 보여준다. 교체 주기는 시작 속도 0.16초에서 최고 속도 0.09초까지 속도에 비례해 짧아진다. walk 포즈일 때는 2px 떠서 발을 딛는 느낌을 준다. v3의 사인파 bobbing은 없앴다.
   - 지면: 대시 6줄과 점 3줄 패턴이 게임 속도 그대로 흐른다. v3보다 촘촘하고 길다.
   - 발밑 먼지: 착지 때 6개, 스텝 교체 때마다 2개.
   - 스피드 라인: 속도 380 이상에서 화면 위·아래 가장자리에 옅은 가로선이 잠깐씩 지나간다. 빈도는 속도에 비례한다.
   - 패럴랙스: 언덕 2겹 0.18배/0.32배(평균 0.25배), 구름 0.1배. 모두 게임 속도에 곱해져서 속도가 오르면 같이 빨라진다.
5. **속도**: 시작 105 → 240 px/s, 최고 175 → 480 px/s. 가속은 시간 기준을 버리고 별 1개당 목표 속도 +5다(48개에서 최고 속도). 목표 속도로는 25 px/s²로 부드럽게 따라간다.
6. **테스트 훅**: `?test=1&speed=max`(처음부터 최고 속도)를 추가했다. `__TEST_RESULT.physics`에 실측 수치를 남긴다(아래 표 참고).
7. **에셋**: `*_walk_v2.png`(라이브러리 원본을 높이 512px로 축소)와 반전본 `*_walk_flip.png`를 추가했다. 코코 walk 원본은 같은 높이로 맞추면 머리가 run보다 작게 보여서(머리 폭 233 vs 264px) 그릴 때만 1.12배로 키운다. 판정 박스는 run 포즈 기준 그대로다.

유지한 것: 캐릭터 선택·저장, 우향 반전, 디자인 시스템(카드·pill·패널), 사운드, 최고기록, delta time, 모바일 조작, 판정 폭 38%, 물웅덩이 무해, 돌멩이 비율 35%, 점프 버퍼 0.18초.

|---|---|

- 최고 기록은 `localStorage`(키 `tinokoko-dino-best`)에 저장된다.

## 판정 수치 (v4 계산 근거)

- 캐릭터 판정 폭(표시 폭의 38%): 티노 `96.8 × 0.38 = 36.8px`, 코코 `85.1 × 0.38 = 32.3px`.
- 장애물 최대 판정 폭: 물웅덩이 `52 × 0.5 = 26px` (돌멩이 19px).
- **필요 클리어 거리** = 캐릭터 판정 폭 + 장애물 최대 판정 폭: 티노 62.8px, 코코 58.3px.
- **점프 수평거리** = 속도 × 체공: 시작 `240 × 0.767 ≈ 184px`, 최고 `480 × 0.783 ≈ 376px`.
- 돌멩이 위로 넘는 구간(판정 높이 30px, `lift ≥ 30`): 시작 속도에서 약 0.03~0.75초. 이 0.71초 동안 171px을 이동해 필요 거리 55.8px의 3배다.
- 자동 조종사: 장애물 판정 왼쪽 끝이 캐릭터 판정 오른쪽 끝에서 `속도 × 0.2초` 안에 들어오면 점프한다. 겹침 구간은 0.2초부터 0.2 + 55.8/240 ≈ 0.43초까지로, 위 구간 안에 있다.

## 자동 검증

결과는 화면 왼쪽 위 배지, `console`, `document.title`, `window.__TEST_RESULT`에 남는다. 판정은 실제 게임 충돌 로직으로 한다.

| URL | 조종 | PASS 조건 |
|---|---|---|
| `?test=1` (`&char=coco`로 코코) | 자동 점프 | 충돌 없이 5개 (60초 안) |
| `?test=1&speed=max` (v4 추가) | 자동 점프, 처음부터 480 px/s 고정 | 충돌 없이 5개 |
| `?test=1&force=puddle&nojump=1` | 점프 금지, 물웅덩이만 | 충돌 없이 3개 통과 |

`__TEST_RESULT.physics`에 남는 값:
- `startSpeed`, `maxSpeed`, `gravity`
- `charHitW`, `obstacleHitWMax`, `clearNeed`
- `sim.start` / `sim.max`: 게임과 같은 물리식을 dt = 1/60으로 돌린 체공·수평거리·최고 높이·비율
- `measured.jumps`: 실제 점프마다 이륙 속도, 체공, 수평거리
- `measured.ratioMin`
- `gapSecMin`: 앞 장애물 꼬리 통과부터 다음 장애물 머리 도착까지의 시간 간격 최소값

- 부정 확인: `?test=1&nojump=1`(돌멩이 섞임, 점프 금지)을 3회 돌렸다. 2회는 돌멩이 충돌로 FAIL(점수 2·0)이었다. 나머지 1회는 장애물 5개가 모두 물웅덩이로 뽑혀 PASS였다(확률 0.65⁵ ≈ 12%). 돌멩이만 게임을 끝낸다는 점은 유지된다.

## 알려진 한계

- **브라우저 범위**: 헤드리스 Chromium 한 종류만 확인했다. 사파리, 파이어폭스, 실제 모바일 기기는 확인하지 않았다.
- **사람 체감은 미확인**: "빠른데 할 만한가"는 자동 조종사와 수치로만 확인했다. 사람이 직접 칠 때의 체감과 아이 대상 테스트는 하지 않았다. 특히 240 px/s 시작은 v3(105)의 2.3배라서 어린 아이에게 빠를 수 있다.
- **중간 속도(265~475)는 자동 테스트로 직접 돌리지 않았다**: 시작 테스트는 5개를 넘는 동안 240→260까지만 오른다. 최고 속도는 별도 모드로 확인했다. 중간 구간은 같은 식(체공 선형 보간, 시간 기준 간격)이라 두 끝점 사이에 있다고 판단했다.
- **walk 원본의 차이**: 라이브러리의 티노 walk 원본은 흰 티에 초록 공룡 그림이 없다(run 원본에는 있다). 빠르게 교체되면 잘 안 보이지만 정지 프레임에서는 차이가 보인다. 새 이미지 생성은 금지라 그대로 썼다.
- **소리**는 귀로 확인하지 않았다 (v3와 같은 신스, 변경 없음).
- **범위 밖 (의도적으로 안 넣음)**: 레벨, 더블점프, 숙이기, 난이도 선택, 새 캐릭터 이미지, 프레임워크.
