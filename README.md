# 티노코코 동시점프 러너 (프로토타입 v1)

크롬 오프라인 공룡 게임과 같은 구조의 달리기 게임. 캐릭터가 두 명이라서, 티노와 코코가 나란히 달리다가 한 번의 입력으로 둘이 같이 점프한다.

- 빌드 없음, 프레임워크 없음. 바닐라 JS + Canvas 한 파일(`index.html`) + 이미지 `assets/` 폴더.
- 구글 코드·에셋은 쓰지 않았다. 메카닉만 참고한 오리지널 구현.

## 파일 구성

```
tinokoko-dino-game/
├── index.html              게임 전체 (CSS·JS 인라인, 한국어 주석)
├── README.md               이 문서
└── assets/
    ├── tino_run_v2.png     티노 달리기 (높이 512px)
    ├── tino_jump_v2.png    티노 점프
    ├── tino_laugh_v2.png   티노 웃음 (부딪힌 뒤)
    ├── coco_run_v2.png     코코 달리기
    ├── coco_jump_v2.png    코코 점프
    └── coco_laugh_v2.png   코코 웃음 (부딪힌 뒤)
```

`assets/`의 6장은 승인된 원본(`tinokoko-pipeline/library/assets/*_v2.png`)을 높이 512px 이하로 줄인 복사본이다. 비율과 투명 배경은 유지했고, 새로 그리거나 생성한 이미지는 없다.

## 실행 방법

**방법 1: 파일 열기 (가장 간단)**
`index.html`을 크롬·엣지·사파리 등 브라우저로 더블클릭하거나 주소창에 끌어다 놓는다. `file://`에서도 동작하도록 이미지는 상대경로로 불러온다.

**방법 2: 로컬 서버**
```bash
cd ~/workspace/tinokoko-dino-game
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000 접속
```

## 조작법

| 입력 | 동작 |
|---|---|
| 스페이스바 / ↑ | 점프 (둘이 동시에) |
| 화면 클릭·탭 | 점프 |
| 게임 시작 전 첫 입력 | 시작 + 첫 점프 |
| 부딪힌 뒤 입력 | 재시작 (부딪힌 직후 약 0.5초는 입력 무시) |
| 우상단 🔊 / 🔇 버튼 | 소리 켜기·끄기 |

- 공중에서 누르는 입력은 무시된다 (이중 점프 없음).
- 장애물을 넘을 때마다 ⭐ +1. 우상단에 "넘은 장애물 수"가 표시된다.
- 최고 기록은 `localStorage`(키 `tinokoko-dino-best`)에 저장된다. 저장이 막혀 있어도 게임은 그대로 동작한다.

## 검증 결과 (2026-10-30)

브리프의 검증 4단계를 모두 실행했다.

1. **파일 존재와 참조 일치**: `index.html`과 `assets/` 6장이 있다. HTML이 참조하는 6개 경로가 실제 파일과 모두 일치한다 (`MISSING` 없음).
2. **로컬 서버 200 응답**: `python3 -m http.server`로 띄운 뒤 curl로 확인했다.
   - `index.html` → 200 (text/html)
   - 이미지 6장 → 모두 200 (image/png)
3. **JS 문법 검사**: `index.html`의 인라인 `<script>`를 뽑아 `node --check`를 실행했다. 문법 오류 없음.
4. **이 문서 작성**: 위 항목을 기록했다.

추가로 헤드리스 Chromium(로컬에 캐시된 빌드)으로 확인했다. 브리프에 없던 검증이다.
- `file://`로 열었을 때 이미지 6장이 모두 그려졌다. 두 캐릭터의 표시 높이가 같고 시작 안내 문구가 보인다.
- CDP로 스페이스바를 주기적으로 눌러 실행했다. 점수가 1, 2까지 올라갔고 충돌 후 "풍덩! 다시 해볼까?" 상태로 전환됐으며, 재시작 후 점수가 0으로 돌아가고 최고 기록(2)이 저장·표시됐다.
- 실행 중 발생한 JS 예외(uncaught exception)와 콘솔 에러는 0건이었다.

## 알려진 한계

- **브라우저 테스트 범위**: 헤드리스 Chromium 한 종류에서만 확인했다. 사파리, 파이어폭스, 실제 모바일 기기에서는 확인하지 않았다.
- **소리는 귀로 확인하지 않았다**: WebAudio 코드는 실행 오류 없이 돌아가는 것만 확인했다. 음색과 음량은 직접 들어봐야 한다.
- **충돌 판정 해석**: 브리프는 "hitbox를 좌우/상하 25% 안쪽"이라고 했다. 발끝(아래쪽)까지 25% 줄이면 땅에 붙은 물웅덩이에는 아예 닿지 않아서, 발끝은 줄이지 않고 좌우와 위쪽만 25%씩 줄였다. 장애물 판정도 같은 규칙을 적용했다.
- **장애물 간격은 이론값 기준**: 최소 간격은 최고 속도에서 점프 체공 시간(반동 포함 약 1.27초)과 여유 60px로 계산했다. 실제 플레이로 "넘을 수 있는지"를 체감 검증하지는 않았다.
- **난이도는 추정값**: 시작 속도 170, 최고 속도 360(월드 px/s), 점프 높이 140, 중력 1000. 유아 대상 테스트를 거치지 않은 값이므로 조정이 필요할 수 있다.
- **재시작 시 점수 초기화**: 부딪힌 뒤에는 점수가 화면에 유지되고, 재시작하면 0으로 돌아간다.
- **v1 범위 밖 (의도적으로 안 넣음)**: 앱스토어·서버·로그인·분석·광고·결제, 난이도 선택, 레벨, 더블점프, 숙이기, 캐릭터 신규 이미지 생성, 프레임워크.
